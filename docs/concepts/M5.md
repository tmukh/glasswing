# M5 concepts: drawing what the model does

What M5 introduced, how each idea works, and where it lives in the code
(`takodana.dev/src/components/glasswing/`).

## 1. What gets drawn, and from which numbers

Every token the worker processes arrives as one message with flat arrays from the engine's trace
(`step.rs`):

| view | shape | drawn as |
|---|---|---|
| MLP activations | [8, 1024] | each layer's 32×32 grid of glowing points |
| attention | [8, 6, pos+1] | head orbs (brightness = focus) and word highlights in the text |
| residual stream | [9, 384] | the strip climbing the right side of the tower |
| top-20 next tokens | ids + probabilities | the "Next token" bars |

Colour encodes **sign** (gold positive, blue negative) and brightness encodes **magnitude**. Each layer
is scaled to its own 98th percentile: a few neurons are much larger than the rest, and scaling by the
maximum would leave one bright dot in a dark grid.

**Head focus** = how far the head's largest attention weight is above uniform:
`(max − 1/n) / (1 − 1/n)`. A head spreading its attention evenly is dim; one that looks at a single
token is bright.

## 2. Separating computation from playback

The worker computes as fast as it can (hundreds of tokens per second); people can't follow that. The
page keeps a queue and plays steps back at a chosen speed (default 6 tokens/s), and a pulse carries
each token up the tower in that time. Computation and animation are decoupled, so slow devices animate
the same way, just with less margin. The measured browser speed is shown after each story.

## 3. three.js without React in the render loop

`Tower.ts` is a plain class: one `THREE.Points` cloud for all 8,192 neurons and one for the residual
stream, both with per-vertex colours. Each frame updates the colour buffers (blending the previous
token's state into the new one as the pulse passes each layer) and renders. React only owns the
controls and text. This keeps the render loop at a stable frame rate: no React re-render for every
animation frame. The loop pauses when the canvas is off-screen (`IntersectionObserver`), and
`prefers-reduced-motion` turns off the pulse and auto-rotation.

## 4. Attention in the text

Hovering a word shows that token's attention over all earlier words for the chosen layer and head (or
the mean of the heads). Two details matter for reading it honestly:

- Shading is **relative to the strongest visible weight** in the row; absolute weights of 1–5% would
  all look the same.
- The **start-of-story token is excluded** from that scale. Many heads "park" most of their attention
  on it when nothing else is relevant (an *attention sink*), which would make every real word look
  irrelevant. The share parked there is printed below the text instead.

## 5. Serving the model files

`scripts/fetch-glasswing.mjs` runs before every build: it downloads the release files listed in
`glasswing.lock.json` and checks each one's sha256, so the site only ever serves bytes that match the
lock file. They live under `/glasswing/<release tag>/`: a new model gets a new path, so nginx marks the
files `immutable` for a year, and Cloudflare can cache them at its edge (the weights are named
`model.bin` because `.bin` is on Cloudflare's list of cached extensions and `.safetensors` isn't). The
model is only downloaded when a visitor clicks "Load the model".
